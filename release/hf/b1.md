# Bulwark-B1: driver monitoring model for drowsiness and distraction detection (research preview)

Bulwark-B1 is a research video model for driver monitoring systems (DMS). From a 2-second clip of a camera facing the driver, it detects signs of drowsiness (eye closure, blinks, yawns) and distraction (phone use, eating, drinking).

![An AI-generated clip of a driver reaching for a phone and texting, with Bulwark-B1's outputs for each 2-second window: a phone alert in one window, at 0.48 against a threshold of 0.37, and texting as the top activity.]({{ code_raw_url }}/docs/media/bulwark-b1-demo.webp)

*AI-generated clip (Google Veo), no real person. Bulwark-B1's unedited outputs from `bulwark predict`: a phone alert in the 3-5 s window while the driver texts. On other AI-generated clips from the same camera view it misses yawns, shut eyes and a glance out of the side window. White tick = B1's threshold; blink is shown but is not an alert sign.*

## What it detects

For each clip, Bulwark-B1 gives one value per output below: signs of eye closure and PERCLOS (percentage of eyelid closure), yawning, head pose (yaw, pitch, roll), phone use while driving, texting, eating and drinking. The last column says whether a dataset's own labels (ground truth) checked the output.

{{ labels_table }}

Notes on some outputs:

- **PERCLOS** is here the share of the clip's frames with the eyes closed. Drowsiness research averages it over 60 seconds or more; `bulwark predict` adds that rolling 60-second value.
- **Eye openness** was checked on MRL Eye's still images only.
- **Head yaw, pitch and roll** are returned divided by 90, from -1 to 1. Multiply by 90 for degrees. Pitch is positive when the head tips down relative to the camera, so 0 means facing the camera, not a level head. Yaw is positive when the person turns to their own left.
- **Head nod:** do not use it in v0. Its training labels came from a rule that had the pitch sign the wrong way round, so it fired when the head rose and came back rather than on a nod. The sign error is fixed in the code for the next model, but the rule still cannot tell nodding off from looking down, and no ground truth has checked it.
- **Activity** is one of: attentive, looking away, phone call, texting, eating, drinking, talking, reaching, grooming, adjusting controls, reading, interacting with an object, or other. The model file also has classes that were never trained (below).
- **Camera type** (RGB colour or near-infrared) and **low light** describe the recording, not the driver, so the evaluation uses them only as sanity checks.

The model file also has outputs that were not trained: {{ untrained_outputs }}. They return arbitrary values, and `bulwark predict` leaves them out. {{ untrained_classes }} {{ not_trained_on_images }}

## Quick start

You will install the Bulwark code, download Bulwark-B1 and run it on a video of your own.

1. Request access on this page. Access is granted as soon as you submit the form.
2. Install the code and the Hugging Face command-line tool, and log in with a [Hugging Face access token](https://huggingface.co/settings/tokens):

   ```bash
   pip install {{ github }}/archive/refs/tags/{{ code_tag }}.zip huggingface_hub
   hf auth login
   ```

3. Download the weights and run them on a video, such as `my_clip.mp4`:

   ```bash
   hf download {{ repo_id }} --local-dir bulwark-b1
   bulwark predict bulwark-b1 my_clip.mp4
   ```

`bulwark predict` prints one line per 2-second window, one window every second. `--out timeline.json` saves every output, the decision thresholds and the rolling PERCLOS. In Python:

```python
from bulwark.inference import load, predict_video

model = load("bulwark-b1")  # the downloaded folder
for window in predict_video(model, "my_clip.mp4"):  # 2-second windows, one every second
    print(window["start"], window["outputs"]["eyes_closed"], window["outputs"]["phone"])
```

- **Input:** `predict_video` takes 16 frames from each 2-second window, every k-th frame with `k = max(1, round(2 * fps) // 16)`, and letterboxes them to 256 x 256. To pass your own frames, call `model.predict(frames)` with a (16, height, width, 3) uint8 RGB array sampled the same way.
- **Output:** for each window, a probability for each yes/no output, one per class for activity and camera type, and a value for the others.
- **Calibration:** the weights record temperatures and decision thresholds fitted on the validation people, separately for video and still images. {{ image_calibration }} AUC Distracted Driver v2 has no validation people. `load` applies the temperatures, and `model.thresholds_for("video")` gives the thresholds. Set your own on your own data. See [calibration files]({{ code_url }}/docs/inference-and-adapters.md#calibration-files).
- **Without the download step:** `load` and `bulwark predict` also take the repository id, `{{ repo_id }}`.

Tested on 2026-11-13 with inferensys-bulwark 0.1.0 installed from the v0.1.0 tag into a new virtual environment (Python 3.11.13, PyTorch 2.15.0, huggingface_hub 2.4.0) on macOS on an Apple M1 Max, with the weights downloaded from this repository.

## Intended use

Bulwark-B1 is for research on a driver's state as seen on video.

- Research on driver drowsiness detection and driver fatigue monitoring.
- Research on distracted driver detection.
- A base model: its 512-number state embedding can train small task adapters for labels of your own.
- Outputs as signals that support a decision, such as an alert to the driver. They can also feed a safety system that has its own logic and validation.

It is for researchers, in academic and other non-commercial research.

Fleet operators, video telematics and AI dash cam providers, car makers (automotive OEMs) and their Tier-1 suppliers, and safety teams in industry need a commercially licensed model from Inferensys for product work, pilots and evaluations, as does any other commercial use. See [Commercial models](#commercial-models).

## Limitations

The main limits of Bulwark-B1 and its evaluation:

- **Few people:** Drive&Act has 15 drivers, the DMD face-camera video 14 people and MRL Eye 37 people. Each test set holds only 3 of them.
- **No results by group:** no video dataset records age, sex or skin tone, so how results differ across groups of people is unknown.
- **Narrow conditions:** the video is mostly from cars, much of it near-infrared. There are no thermal cameras. Bulwark is not tested in trucks, buses, forklifts, mining or heavy-equipment cabins.
- **Short clips:** each clip covers about 1 to 2 seconds. Drowsiness develops over minutes, so combine outputs over consecutive clips.
- **Head pose, mouth open and head nod:** learned only from a face-landmark model's labels, and not checked against ground truth. The head nod labels were wrong (see the notes on outputs): ignore that output.
- **Blink and yawn:** learned from one camera of one dataset (DMD).
- **Eye openness on video:** it leans towards open, and no dataset could check it on video.
- **Looking down:** the face model cannot tell looking down from closed eyes, so its closed-eye readings were not used in training.
- **Still images:** the image datasets, MRL Eye and AUC Distracted Driver v2, give ground truth only for the eyes, eyeglasses, phone at ear, activity and camera conditions. A face model also labelled head pose and mouth open on AUC's images. On a still image, the other outputs rely on what the model learned from video, and those not trained on still images are left out.
- **New camera positions:** scores were lower on a camera position that training never used (see [Results](#results)). In research, check it on your own cameras.
- **Not calibrated for real settings:** probabilities reflect the mix of training datasets, not any real setting. Research on other data needs thresholds set on that data.
- **Untrained outputs:** the outputs listed as not trained under [What it detects](#what-it-detects) return arbitrary values.

## How it works

Bulwark-B1 builds on a video encoder that Meta trained on large amounts of unlabelled video. Inferensys adapted the encoder with small LoRA adapters and trained a multi-task head, with one output per sign, on four driver datasets. The head's summary of each clip, a 512-number state embedding, can also train adapters for new labels.

<details>
<summary>Architecture and training details, for researchers</summary>

- **Encoder:** Meta's V-JEPA 2.1 ViT-B/16 ([V-JEPA 2.1 paper](https://arxiv.org/abs/2603.14482)), about 86.8M parameters, frozen during training.
- **Adapters:** rank-16 LoRA on the `qkv`, `proj`, `fc1` and `fc2` layers of the last 4 blocks, plus the final norm, about 0.79M trained parameters. In this release they are merged into the encoder.
- **Head:** the encoder's tokens are pooled into 25 summary tokens, then a 2-layer transformer, about 6.8M parameters. Training updates 7.56M parameters in all.
- **Outputs:** raw logits per output, decoded with a sigmoid (yes/no), a softmax (classes) or a scaled sigmoid (ranges). The state embedding has 512 values.
- **Training:** the LoRA fine-tune started from a heads-only run on the same data, chosen by 5-fold cross-validation. This release is the fine-tune checkpoint with the best validation score.
- **Calibration:** one temperature per output and media type, fitted on the validation people.
- **Parameters:** {{ parameters_exact }} values in `model.safetensors`, counted from its header.
- More in [Architecture: Bulwark-B1]({{ code_url }}/docs/architecture.md#bulwark-b1) and [Training: B1 LoRA fine-tune]({{ code_url }}/docs/training.md#3-b1-lora-fine-tune).

</details>

## Training data

Bulwark-B1 learned from four research datasets of people in vehicles. No dataset frames are reproduced on this page, in this repository or on GitHub.

| Dataset | People: train / validation / test | Used for |
|---|---|---|
| [Drive&Act](https://www.driveandact.com/) | 10 / 2 / 3 drivers, the dataset's own split | Activity, phone, phone at ear, food and drink, on 5 near-infrared views and 1 colour view |
| [DMD](https://dmd.vicomtech.org/), face camera | 9 / 2 / 3 people | Eyes closed, PERCLOS, blink, yawn, phone, phone at ear, drink and activity, on colour video |
| [MRL Eye](https://mrl.cs.vsb.cz/eyedataset.html) ([archived copy](https://web.archive.org/web/20260516/https://mrl.cs.vsb.cz/eyedataset.html)) | 31 / 3 / 3 people | Eye openness, eyes closed and eyeglasses, on near-infrared eye images |
| [AUC Distracted Driver v2](https://heshameraqi.github.io/distraction_detection) | the authors' split by driver; no validation set; test is one group | Phone at ear and activity, on colour still images |

Drive&Act's inner-mirror camera is not used in training. Its clips of the 3 test drivers form a new-camera test.

<details>
<summary>Labels from other models and label rules, for researchers</summary>

- A face-landmark model (MediaPipe Face Landmarker) labelled mouth open, head pose and head nod, and eye openness and PERCLOS on video. Its "eyes open" readings also became labels where a dataset had none. Its closed-eye, blink and yawn readings were not used.
- One label comes from a rule: a DMD clip whose eyes stay closed for 1 second or more is labelled as a microsleep. B1 did not train that output.
- Labels from the face model and the rule count half as much as ground truth in training, and are never scored.
- The object detector (RF-DETR) and the vision-language model (Qwen3-VL) that Bulwark can also use were not run for this release.
- Details are in the [data card]({{ code_url }}/docs/data-card.md#labels).

</details>

## How we evaluated

Bulwark's evaluation follows these rules:

- No person is in more than one split, and the splits are checked for leaks before scoring.
- Only the datasets' own labels (ground truth) are scored, never labels from other models.
- Each score is shown with a constant baseline.
- Decision thresholds and temperatures are tuned on the validation people, never on test.
- A new-camera holdout, Drive&Act's inner-mirror camera, is scored on its 3 test drivers.
- The report also gives calibration error and results by camera condition.

The protocol is in [Evaluation]({{ code_url }}/docs/evaluation.md).
